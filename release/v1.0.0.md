# H2A2H v1 Stable Release Gate

This document is the release checklist for the first stable H2A2H protocol release.

The checklist records implemented capabilities separately from final promotion.
Checked implementation items do not make the protocol stable while any final
promotion gate below remains unchecked.

## Normative layer

- [x] Normative H2A2H v1.0 specification exists.
- [x] Terminology and protocol invariants are explicit.
- [x] Canonical lifecycle/state transitions are defined.
- [x] OpenIntent integration is defined.
- [x] OpenDelegation Protocol is defined.
- [x] OpenEntityChannels is defined.
- [x] Proof-of-Human-Return is defined.
- [x] Identity and responsibility-chain semantics are defined.
- [x] Canonical message envelope is defined.
- [x] Security and audit/provenance profiles are defined.
- [x] MCP and A2A bridge semantics are defined.
- [x] Versioning and compatibility rules are defined.
- [x] JSON Schema 2020-12 normative artifacts are published.
- [x] Core invariants have a TLA+ model.

## Executable layer

- [x] Reference SDK/runtime A exists.
- [x] Delegation sessions enforce expiry and revocation.
- [x] Human-in-the-Healing-Loop is resumable and auditable.
- [x] OpenEntityChannels forger/adapters exist.
- [x] Human→Agent→Agent→Human E2E exists.
- [x] Organization, Service, Device and Government Entity E2E scenarios exist.
- [x] Independent Reference Implementation B exists without shared runtime code.
- [x] Reference A↔B interoperability is tested bidirectionally.
- [x] Two independent interoperability channel profiles are exercised: direct serialized JSON and HTTP request/reply.

## Verification layer

- [x] Strict TypeScript typecheck is part of CI.
- [x] Normative schema compilation/fixtures are part of conformance.
- [x] Lifecycle, delegation, replay protection, audit and version compatibility are tested.
- [x] Independent implementation interoperability is part of `npm test`.
- [x] Dependency audit is part of CI and release workflows.
- [x] Dependency graph is locked and CI/release use `npm ci`.
- [x] `npm run release:gate` verifies presence/version of required v1.0 artifacts.
- [x] Main branch after independent implementation merge is green.
- [x] Every ordinary recovery checkpoint has conformance coverage.
- [x] Recovery from `EXECUTING` fails closed without explicit idempotent retry or reconciliation.

## Final promotion gates

- [ ] Every normative document has completed review and no longer says `draft` ([#255](https://github.com/suissa/H2A2H/issues/255)).
- [ ] An independent security/conformance review has no unresolved critical or high findings ([#255](https://github.com/suissa/H2A2H/issues/255)).
- [ ] All GitHub issues and pull requests are closed at the release commit.
- [ ] A repository ruleset prevents update or deletion of `refs/tags/v*` ([#254](https://github.com/suissa/H2A2H/issues/254)).
- [x] The premature historical `v1.0.0` tag/release is preserved as evidence and its GitHub release is verified withdrawn/prerelease ([#256](https://github.com/suissa/H2A2H/issues/256)).

## Immutable-release requirements

After Conformance CI succeeds on `main`, the release workflow checks the
validated commit and package version. A stable version must not be created
until all final promotion gates are checked and the repository has no open
issues or pull requests. Because the premature `v1.0.0` identity is permanently
consumed, the first valid stable release must be `v1.0.1` or later and must:

- rerun the release artifact gate, strict typecheck, build, full conformance and dependency audit;
- create the selected stable tag only if it does not already exist;
- reject an existing tag that points to a different commit;
- generate machine-readable `conformance-report.json` for the validated commit;
- upload the report as a workflow artifact;
- create the stable GitHub Release with the conformance report attached.

Issue #27 is complete only after those immutable-release requirements have succeeded.
