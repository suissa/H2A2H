# H2A2H v1.0.0 Release Gate

This document is the release checklist for the first stable H2A2H protocol release.

## Normative layer

- [x] Normative H2A2H v1.0 specification exists.
- [x] Terminology and protocol invariants are explicit.
- [x] Canonical lifecycle/state transitions are defined.
- [x] OpenIntent integration is defined.
- [x] OpenDelegation Protocol is defined.
- [x] OpenEntityChannels is defined.
- [x] Proof-of-Human-Return is defined.
- [x] Identity and responsibility-chain semantics are defined.
- [x] Canonical message envelope is defined.
- [x] Security and audit/provenance profiles are defined.
- [x] MCP and A2A bridge semantics are defined.
- [x] Versioning and compatibility rules are defined.
- [x] JSON Schema 2020-12 normative artifacts are published.
- [x] Core invariants have a TLA+ model.

## Executable layer

- [x] Reference SDK/runtime A exists.
- [x] Delegation sessions enforce expiry and revocation.
- [x] Human-in-the-Healing-Loop is resumable and auditable.
- [x] OpenEntityChannels forger/adapters exist.
- [x] Human→Agent→Agent→Human E2E exists.
- [x] Organization, Service, Device and Government Entity E2E scenarios exist.
- [x] Independent Reference Implementation B exists without shared runtime code.
- [x] Reference A↔B interoperability is tested bidirectionally.
- [x] Two independent interoperability channel profiles are exercised: direct serialized JSON and HTTP request/reply.

## Verification layer

- [x] Strict TypeScript typecheck is part of CI.
- [x] Normative schema compilation/fixtures are part of conformance.
- [x] Lifecycle, delegation, replay protection, audit and version compatibility are tested.
- [x] Independent implementation interoperability is part of `npm test`.
- [x] Dependency audit is part of CI and release workflows.
- [x] `npm run release:gate` verifies presence/version of required v1.0 artifacts.
- [x] Main branch after independent implementation merge is green.

## Tag-time requirements

The following are intentionally verified only from the immutable `v1.0.0` tag:

- release workflow passes typecheck, build, full conformance and dependency audit;
- machine-readable `conformance-report.json` is generated for the tagged commit;
- the report is uploaded as a workflow artifact;
- GitHub Release `v1.0.0` is created with the conformance report attached.

Issue #27 is complete only after those tag-time requirements have succeeded.
